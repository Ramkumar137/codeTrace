                                How CodeTrace works
                                
        
                                CodeTrace takes a notebook from source inspection to evidence-backed review. You stay in control: analysis does not execute code, repairs require your approval, and experiments run only when you explicitly start them.
                                

        
                                
          
                                The complete project workflow
                                
          
                                  
            
                                1. 
              01
              
                                  Upload a notebook
                                  CodeTrace validates the Jupyter notebook and shows its cells and safe, whitelisted metadata. Upload does not execute code or open notebook-referenced files.
                                  
            
                                  2. 
            
                                2. 
              02
              
                                  Trace the ML workflow
                                  Static Python analysis recognizes supported data, preprocessing, split, model, prediction, and evaluation operations, then links operations using source-visible variable references.
                                  
            
                                  3. 
            
                                3. 
              03
              
                                  Review evidence and dataset context
                                  Inspect potential risks with cell and line evidence, related variables, confidence, and limitations. Optionally profile an explicitly selected CSV or compare train/test CSVs for row, identifier, or group overlap in light of your evaluation objective.
                                  
            
                                  4. 
            
                                4. 
              04
              
                                  Approve a supported repair
                                  Review the proposed source changes and approve or reject them. Supported repairs are deterministic and narrow; the corrected notebook is separate, and the original remains unchanged.

                                5. 
              05

                                  When Docker and the runner are available, start separate offline, resource-limited runs of the original and corrected versions.                                 What is CodeTrace’s novelty?
                                
          
                                The contribution is the connected, evidence-preserving workflow—not the claim that CodeTrace invented leakage detection or automatic repair. CodeTrace links a potential evaluation issue to notebook source, lets a person review a narrow repair, keeps the original and corrected experiments separate, checks the repair against saved source and execution evidence, and reports metric impact only when comparisons are justified.
                                
          
                                This makes the system’s central question: Can a reviewer follow an evaluation-risk finding through an approved correction and controlled re-execution to see what changed, what was verified, and what remains uncertain?
                                
          
                                This integration is an implemented project contribution, not proof of scientific priority or superiority. A research novelty claim still requires a literature review and empirical comparison with existing detection, repair, and validation tools.

                                Your model passed the test. But was the test trustworthy?
                                
        
                                Machine-learning results can look convincing while the evaluation process quietly reuses training data, fits transformations using held-out examples, or carries information from the target into the features. These mistakes can inflate scores and make a model less reliable when it meets new data.
                                
        
                                
          
                                Follow the evidence through the notebook
                                
          
                                CodeTrace inspects notebook source without running it. It identifies recognizable data-loading, preprocessing, split, model, prediction, and evaluation calls, then connects operations when source code shows shared variable references. Each extracted operation points back to its cell and line so you can inspect the original context.
                                
        
                                
        
                                
          
                                Our contribution, stated clearly
                                
          
                                CodeTrace connects evidence-linked notebook diagnosis to human-approved repair, isolated re-execution, scoped repair verification, and cautious metric comparison in one traceable workflow. The contribution is this integration and the evidence it preserves—not a claim to be the first leakage detector or code fixer. Its scientific novelty and value must be established through literature review and empirical evaluation.

                                Trace, audit, and review
                                
          
                                The pipeline trace is a source-based view of the workflow. The audit checks a limited set of recognizable patterns and presents findings with evidence, confidence, and review guidance. A flagged pattern is a potential risk, not proof of a defect.
                                
          
                                For supported findings, CodeTrace can propose a repair. You review and approve or reject it; an approved corrected notebook is stored separately so the original stays unchanged. You can generate evidence reports from the analysis and any saved repair, execution, verification, and comparison records.
                                
        
                                
        
                                
          
                                Interpret with care
                                
          
                                Static analysis cannot establish every runtime fact. Variable names and source order may not reflect actual data contents or execution order; dynamic code, aliases, hidden state, and dataset contents may be outside the analyzer’s reach. CodeTrace never loads notebook-referenced paths or URLs during analysis. Notebook cells run only after an explicit request in Experiments, through the isolated execution service; execution success does not prove a repair is correct or a model trustworthy.
                                
        
                                
        
                                
          
                                Frequently asked questions
                                
          
                                
            What services does CodeTrace provide?
            
                                Choose a service below to learn what it does and what to expect.
                                
            
                                
              
                                
                Notebook inspection and pipeline tracing
                
                                Upload a Jupyter notebook to validate its structure, inspect cells and recognized ML operations, and explore a source-linked pipeline graph. Analysis does not execute notebook code.
                                
              
                                
              
                                
                Leakage and evaluation-risk review
                
                                Review supported static warnings for patterns such as preprocessing before a split, target-column inclusion, or suspicious use of evaluation data. Findings show evidence and limitations; they are not runtime proof.
                                
              
                                
              
                                
                Dataset profiling and train/test comparison
                
                                Profile an explicitly selected CSV using aggregate summaries. Compare separately uploaded train/test CSVs for exact-row and selected identifier/group overlap. Objective-aware guidance distinguishes unseen-group testing from future prediction for known groups; the comparison does not inspect notebook paths or infer intended policy.
                                
              
                                
              
                                
                Human-reviewed notebook repairs
                
                                Inspect a deterministic repair proposal, approve or reject it, and generate a separate corrected notebook for supported patterns. Complex or ambiguous repairs remain for manual review.
                                
              
                                
              
                                
                Isolated experiment execution
                
                                When Docker and the runner image are available, explicitly run the original and corrected notebooks in separate offline containers with resource limits and only the datasets you attach.
                                
              
                                
              
                                
                Repair verification and metric comparison
                
                                Compare saved original/corrected execution records, evaluate evidence for the approved repair, and show labeled metric changes only when recorded settings support comparison. This does not prove overall model validity.
                                
              
                                
              
                                
                Evidence report generation
                
                                Generate HTML, PDF, and JSON artifacts from saved analysis, repairs, experiments, and verification records. The report identifies missing evidence and limitations.
                                
              
                                
            
                                
          
                                
          
                                
            How does the full CodeTrace workflow work?
            
                                Upload and inspect a notebook, review evidence-linked risks, approve a supported repair, explicitly run both versions when isolated execution is available, verify the specific repair, compare metrics only when configurations are comparable, and generate a report. Open the workflow page for the step-by-step diagram and details.
                                
          
                                
          
                                
            What does our project do?
            
                                CodeTrace helps review machine-learning notebooks for recognizable data leakage and evaluation risks. For example, if a scaler is fitted on all feature data before the train/test split, it can connect that source pattern to the relevant cells, explain why it may matter, and offer a supported repair for your review.
                                
          
                                
          
                                
            Who can use CodeTrace?
            
                                Students, instructors, and practitioners can use it to inspect a notebook, discuss a possible evaluation flaw, or support a code review. It is a review aid, not a replacement for domain expertise or a complete audit.
                                
          
                                
          
                                
            Does a tool like this already exist?
            
                                There are notebook-analysis, code-quality, and machine-learning auditing tools. CodeTrace does not claim to be the first or only tool for detecting leakage. It focuses on making a limited set of notebook evaluation-risk findings traceable to source and reviewable in one workflow.
                                
          
                                
          
                                
            How is CodeTrace different from other projects?
            
                                It combines source-linked pipeline reconstruction, evidence-bearing findings, human-reviewed repair proposals, separate original and corrected notebook records, and reports that preserve limitations. These capabilities are connected so a reviewer can follow evidence across the workflow; each analysis remains bounded and may miss issues.
                                
          
                                
          
                                
            What are the novelty and unique features added?
            
                                The implemented project contribution is the integrated, traceable review workflow: findings link to notebook cells and pipeline nodes; supported repairs require explicit approval and preserve the original; and reports retain available evidence and uncertainty. This describes what CodeTrace adds as a project, not a claim that its individual rules or methods are scientifically unprecedented.
                                
          
                                
          
                                
            Does uploading a notebook execute it?
            
                                No. Upload and analysis inspect the notebook source without executing code or opening paths and URLs referenced in it. Execution is a separate action and is available only when the isolated execution service is configured.
